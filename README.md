## Про проєкт

AvelRen допомагає стежити за станом вантажних черг: бачити поточні показники, переглядати їхню динаміку та отримувати сповіщення за обраними умовами. Сервер накопичує спостереження щохвилини, а Android-застосунок отримує дані через власний API проєкту.

Застосунок неофіційний. Показники залежать від первинного джерела; перед поїздкою їх варто перевірити в офіційному сервісі. Розрахункові прогнози мають бути чітко відокремлені від виміряних даних.

| Напрям | Призначення |
| :--- | :--- |
| Android-застосунок | Поточна черга, графік змін, персональний моніторинг і сповіщення |
| Сервер | Збір спостережень, історія та API для застосунку |
| Експлуатація | Контроль стану сервісу, резервні копії та перевірка відновлення |

## Архітектура

Схема описує наявний проєкт, який переноситимемо сюди поетапно.

```mermaid
flowchart LR
    source["єЧерга"] -->|"Раз на 60 секунд"| collector["Збір спостережень"]
    collector --> database[("База даних та історія")]
    database --> api["Власний API"]
    api --> android["Android-застосунок"]
    database --> notifier["Сервіс сповіщень"]
    notifier --> push["Firebase Cloud Messaging"]
    push --> android
    database --> backup["Зашифровані резервні копії"]
```

До первинного джерела звертається лише серверний збирач. Застосунок працює через наш API. Кожен цикл збору записується, зокрема невдалий.

Джерело даних — [єЧерга](https://echerha.gov.ua/). Перевірений порядок отримання даних, заголовки та обмеження описані в [контракті інтеграції](INTEGRATION.md). Перед змінами діють [правила агентів і розробників](AGENTS.md).

## Організація роботи

Ми поступово об'єднуємо код і документацію в одному приватному репозиторії. Кожен етап матиме окрему перевірювану зміну та опис результату українською.

- [План перенесення](docs/MIGRATION.md): послідовність, запропонована структура та критерії готовності.
- [Правила роботи](CONTRIBUTING.md): мова, зміни, перевірки та основні технічні обмеження.
- [Аудит перед перенесенням](docs/AUDIT.md): перевірені розбіжності, відкриті питання та порядок виправлень.
- [Контрольний аудит](docs/CONTROL-AUDIT.md): перевірка перенесеного та незавершені матеріали обох джерел.
- [Android](apps/android/README.md): перенесена база 0.1.1, окремі тести та [плашка стану сервера](docs/SERVER-STATUS.md).
- [Що має дійти до телефона](docs/RELEASE-READINESS.md): усі нововведення, блокери та перевірка перед релізом.
- [Аудит нового репозиторію](docs/NEW-REPO-AUDIT.md): перевірені частини, знайдені проблеми та межі готовності.
- [Доступ до ключів і відновлення](docs/SECRETS-RECOVERY.md): єдина точка входу для Android-підпису та серверних секретів.

Перевірки плануємо розділити за компонентами: зміна Android-інтерфейсу має запускати відповідні Android-перевірки. Для спільних залежностей і змін між компонентами запускатиметься ширший набір. Тривалі серверні перевірки збережемо для змін, які їх потребують.

## Стан перенесення

| Етап | Стан |
| :--- | :--- |
| Українське оформлення та початкова документація | Підготовлено |
| Інвентаризація коду, гілок, тегів, PR та відкритих питань | Аудит підготовлено; [код звітності та журнал БД звірено із сервером](docs/PRODUCTION-AUDIT.md) |
| Перенесення компонентів і розділення перевірок | Collector/notifier, БД, API/Admin та [watchdog/телеметрія](docs/WATCHDOG-TRANSFER.md) із розділеним CI; решта попереду |
| Перевірка збірки, сумісності та експлуатаційних процедур | Попереду |
| Перехід на цей репозиторій як основний | Після перевірок |

Старі репозиторії зберігаємо до завершення переходу. Їхнє можливе видалення та перейменування цього репозиторію на `AvelRen` будуть окремим рішенням після стабільної роботи.
