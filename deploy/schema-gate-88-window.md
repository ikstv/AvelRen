  printf "%s %s %s\n" "$(hostname)" "$(id -un)" "$(date -u +%FT%TZ)" | sudo tee /run/avelren-window.lock'

**Будь-який наявний замок → СТОП**, показати вміст, не знімати самому.

## 4. Блок 1 — Гейт B: deploy-дрейф (STOP)

**Виконується всередині вікна, проти актуального `origin/main`.** Пре-вимір
недійсний: `main` рухається, а `git pull` піде на теперішній tip.

```bash
cd /opt/avelren
git fetch origin
git diff --name-only 9bb791f..origin/main -- deploy/
sha256sum /usr/local/sbin/avelren-backup
git show origin/main:deploy/backup.sh | sha256sum
```

База — **чекаут хоста** (`9bb791f`), не образ. Перетин змінених `deploy/`-файлів
зі встановленими копіями порожній і хеші збігаються → без переінсталяції.
Інакше — переінсталювати **в цьому ж вікні**.

`git fetch` тут не мутація деплою, а спосіб мати свіжий `origin/main` для
порівняння; чекаут лишається на `9bb791f` до кроку 5.

## 5. Блок 2 — чи потрібне перезбирання

```bash
git diff --name-only 25ded63..origin/main -- app/
```

**Порожньо → rebuild НЕ потрібен**, образ лишається на `25ded63`, schema-gate у
ньому вже є. **Непорожньо → СТОП і звіт**: це інше вікно, з збіркою за
`schema-gate-deploy.md`.

## 6. Блок 3 — тіло

```bash
git pull --ff-only origin main
git rev-parse HEAD                       # має збігтися з origin/main
```

Далі — прибрати з `docker-compose.override.yml` **лише** блок `migrate`
(remap `/migrations`). **Легасі-DSN пін для чотирьох сервісів НЕ чіпати** — він
до 3C. Зробити копію файлу перед правкою.

```bash
sudo cp -a docker-compose.override.yml docker-compose.override.yml.pre-88
docker compose config | grep -c 'avelren-migrate-pin-009'   # має стати 0 — пін знято
docker compose config --services | grep -c '^migrate$'      # має стати 0 — профіль діє
docker compose up -d --force-recreate api collector notifier watchdog
```

**Дві перевірки, не одна** (пін зник ≠ профіль з'явився): перша нуль доводить, що
пін знято; друга нуль — що профіль активний і `migrate` поза дефолтним набором.
Друга **одиниця → СТОП**: `pull` не приніс #105 або override його перекриває —
гард зник, а профіль не з'явився (найгірший стан). Обидві перевірки — **до**
`up -d`.

## 7. Блок 4 — приймання: п'ять умов, усі

1. У логах **усіх чотирьох** сервісів рядок `schema meets startup requirement`.
2. `docker compose ps` — `migrate` **відсутній** (після `up -d`: каже, що не
   запустився; те, що й не міг би, уже доведено `config --services` у Блоці 3).
3. `SELECT max(version) FROM schema_migrations` = **`009_observability`**.
4. `/api/health` віддає `ok` зі свіжим `last_observation` (< 2 хв).
5. Жодного рестарту в чотирьох контейнерах.

## Стоп-правила

- Будь-який сервіс не піднявся → **відкат**: повернути
  `docker-compose.override.yml.pre-88` на місце, `up -d --force-recreate`
  тих самих чотирьох. Образ не змінювався, тож відкат — це файл і рестарт.
- `schema_migrations` показав **`010`** → **зупинитись негайно** й доповісти.
  Це позачерговий штамп, проти якого стояв пін; розштампувати `migrate` не вміє.
- `migrate` піднявся попри профіль → зупинитись: профіль не застосувався,
  причина в compose-моделі, не в піні.
