```powershell

  --repo ikstv/AvelRen-ORIGINAL `
  --pattern "avelren-upload-2026.jks" `
  --pattern "avelren-upload-2026.pem" `
  --pattern "AvelRen-Production.kdbx"
```

Після завантаження звірити контрольні суми:

```powershell
Get-FileHash -Algorithm SHA256 .\avelren-upload-2026.jks, `
  .\avelren-upload-2026.pem, .\AvelRen-Production.kdbx
```

зберігається на робочому комп'ютері у
`C:\AI\keys\avelren-upload-2026.properties`; цей файл не комітити й не
публікувати.

## Google Play

Старий upload key втрачено. Google не повертав його. Новий ключ створено
локально 22 вересня 2026 року. Того самого дня файл
`avelren-upload-2026.pem` надіслано в Play Console із причиною «Ключ
завантаження втрачено». Google підтвердив отримання запиту й призначив початок
дії нового ключа на **24 вересня 2026 року, 16:08 UTC (19:08 за Києвом)**.
SHA-1 у повідомленні Google збігається з новим сертифікатом:
`6D:26:65:3D:B2:3C:C5:6C:D2:78:5A:2D:88:52:7B:C6:66:B4:70:0D`.

До вказаного часу не намагатися завантажувати AAB, підписаний новим ключем.
Після активації звірити SHA-1 сертифіката в Play Console та лише тоді
продовжувати реліз `0.1.1`.

## Правила

1. Не комітити `.jks`, `.keystore`, `.p12`, `.pfx`, `keystore.properties`,
   `.env` або розшифровані дані KeePass.
2. Не друкувати значення секретів у журналах CI, issue, PR або чатах.
3. Після завантаження файлів перевіряти SHA-256.
4. Ротацію ключа чи пароля документувати тут і створювати новий захищений
   резервний реліз, не замінюючи історичні контрольні суми.


## Звірка чернеткового GitHub Release

Інвентар вище звірено з метаданими вкладень чернеткового release станом на 23 вересня 2026 року. Контрольні суми для раніше описаних KDBX, JKS і публічного сертифіката збігаються; до таблиці додано відсутні вкладення. Вміст файлів не завантажувався й не перевірявся.

Шифрування серверного архіву, properties-файлу та захист приватного SSH-ключа залишаються **неперевіреними**. Розширення `.tar.gz` саме по собі не означає шифрування. Реліз лишається чернетковим: не публікувати, доки не підтверджено шифрування кожного секретного вкладення та окреме зберігання ключа розшифрування. Ця версія документа в Git є канонічною; копія `SECRETS-RECOVERY.md` у вкладеннях релізу може бути застарілою.
