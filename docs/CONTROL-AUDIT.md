# Контрольний аудит перенесення

## Доповнення: read-only перевірка сервера (2026-09-23)

Перевірено без змін на сервері. Docker доступний через `sudo`; шість контейнерів працюють, `avelren-db-1` має стан `healthy`. Тести не запускалися повторно: це лише перевірка стану після тестів, уже виконаних власником.

Узгоджений read-only запит до `schema_migrations` підтвердив рівно версії 001–009. SHA-256 усіх дев'яти записів збігаються з зафіксованим походженням і файлами старого `AvelRen`. Міграції 010/011 у production не застосовані. Жоден DDL/DML чи міграційний крок не виконувався.

Серверний checkout `/opt/avelren` на `81e5b047f8f18c42ca46a59f86495f71d0681af0` (коміт з відкритого старого PR #188) має незакомічені зміни: `app/src/avelren/watchdog.py`, `deploy/telemetry-snapshot.sh` та три резервні/попередні файли compose/privacy. Їх не змінювати й не прибирати; спершу окремо звірити походження з GitHub та визначити, чи потрібне збереження. Встановлений `deploy/PROD_PIN` дорівнює `87cbac095c5e96f390ea475c2a9101bba3954267`.

На сервері `deploy/backup.sh` збігається за SHA-256 з `/usr/local/sbin/avelren-backup` (`de881a23614d40336cb1a7f51495124e30e152b1762f32fb0e90bae9b86dfae9`); `deploy/telemetry-snapshot.sh` збігається з `/usr/local/sbin/avelren-telemetry-snapshot` (`577aa6c1b213174f2ef1a6211a5047a96aeed36f188cdd00cffa0f37ad731966`). Це підтверджує рівність checkout і встановлених копій на момент перевірки, але не замінює звірку з GitHub blob.

Наступний безпечний крок — зіставити незакомічені серверні файли та production pin із точними GitHub-комітами/файлами, нічого не очищаючи на сервері. До цього серверний checkout не є чистим еталоном для перенесення.

їхня наявність не доводить можливість відновлення.

## Порядок наступних кроків

1. Окремо виправити й перевірити достовірність та доставку щоденного звіту.
2. Перенести backup/restore разом із актуалізованими інструкціями ops та
   перевіркою відновлення лише на тимчасовій БД.
3. Завершити production-збірку й захисні перевірки репозиторію.
4. Перенести Android і перевірити його сумісність з API перед переходом.

Продовжуємо один PR із невеликими зрозумілими комітами. Фільтри GitHub PR
враховують весь його diff: доки він містить серверний імпорт, навіть черговий
документальний коміт може повторно запускати всі чотири серверні набори.
Розділення CI не гарантує пропуску цих перевірок усередині накопичувального PR.

## Доповнення: фактичний production drift (2026-09-23)

Через SSH alias `avelren-production` виконано read-only звірку. Серверний HEAD лишається `81e5b047f8f18c42ca46a59f86495f71d0681af0`; робоче дерево має дві змінені tracked-копії (`app/src/avelren/watchdog.py`, `deploy/telemetry-snapshot.sh`) і три не відстежувані резервні файли. Резервні файли не читалися та не змінювалися; їхні розміри й SHA-256 зафіксовано лише для ідентифікації: privacy policy 6488 bytes / `e5a8e239fd9672fbf35eefca12f3fa4388286fa36b85dc3942401bc45e035e4a`; compose backup 1105 bytes / `e4f3d173d82355e0bd5a2c070cdf46a6226b2d28d55ddb976ad8729082eee813`; pre-88 compose 1249 bytes / `dc1fffd65b2ac536ab6d97ca0f71c8a7d3cce02859fde3d8f26809f8f2fa6cdd`.

Read-only `docker exec` показав, що `/app/src/avelren/watchdog.py` у запущеному `avelren-watchdog-1` має SHA `85bd832bec5bd71d4c301f5fc73d2364966e52fd0641c3b64f5548b4050dee2d`, тобто контейнер реально виконує незакомічений серверний watchdog-код, а не версію PR #188. Файл telemetry за вказаним шляхом у контейнері відсутній; хостова встановлена копія раніше звірена із серверним checkout, але не з образом.

**Висновок і межа перенесення:** PR #188 не відображає повністю поточну production-поведінку. Особливо чутлива зміна — вимкнення аварійних і recovery push-повідомлень, тоді як health incidents лишаються в БД/логах і зводяться до щоденного звіту. Не відновлювати сповіщення, не замінювати файли на сервері й не переносити цей diff у новий репозиторій без окремого рішення власника. Наступний крок — зберегти цей production diff у контрольованій гілці/patch після узгодження, перевірити його семантику та покриття тестами; резервні файли окремо класифікувати, не видаляючи.
