# Звірка телефонних доказів — 22.10.2026

## Висновок

Сповіщення вже перевіряли на реальному телефоні. Не потрібно оголошувати всю телефонну перевірку нульовою або повторювати всі базові сценарії. Водночас результати прив’язані до конкретного APK і не приймають автоматично зміни, що з’явилися в main пізніше.

## Що підтверджено аудитом 04.10

Джерело: [ANDROID-SYSTEM-VOICE-PHONE-2026-10-04.md](ANDROID-SYSTEM-VOICE-PHONE-2026-10-04.md).

- Локальний системний голос для п’яти КПП — PASS; власник підтвердив, що почув усі п’ять повністю.
- Локальне скасування голосу під час фрази через ACK — PASS.
- Один реальний фоновий FCM-прогноз Чопа з голосом, почутим власником — PASS.
- Точний дублікат другого прогнозу реально отримано, але голос не стартував удруге — PASS.
- Точний кандидат: `ua.avelren.app.pushqa`, `1.0.3-push-qa`, versionCode 6, SHA-256 `d6ef883972679de5d4844f81a8732f5e3731c488b96f0e443f03838c5f1838c5`; Xiaomi 22071212AG, Android 15/API 35.

Це доказ для вказаного QA APK і зазначених сценаріїв, а не для поточної main чи Google Play. У тому аудиті FCM для Рави-Руської, серверний ACK, locked-screen матриця, overflow/deadline, відсутній TTS і lifecycle abort не були прийняті. Для другого прогнозу технічне завершення зафіксоване, але підтвердження чутності власником очікувалося.

## Що змінилося після тесту

- [PR #144](https://github.com/ikstv/AvelRen/pull/144): threshold/ETA повторюються до ручного скасування; ACK не завершує моніторинг.
- [PR #146](https://github.com/ikstv/AvelRen/pull/146): Android звіряє активні сповіщення після успішного DELETE підписки/ETA-цілі.
- [PR #147](https://github.com/ikstv/AvelRen/pull/147): ACK оновлюється для кожної нової доставки; notifier записує час після успішного send.

Тому на актуальному APK лишається цільово прийняти поведінку threshold і ETA, природний повтор через п’ять хвилин, «ОК» і повторне «ОК», foreground reconciliation та DELETE/cancel. Доказ має містити точний commit, версію APK, SHA-256 і результат кожного сценарію.

## Безпечні межі

Ця звірка лише документаційна. Вона не надсилала push, не змінювала production і не приймає Google Play. Не повторювати вже прийняті базові сценарії без діагностичної потреби. Будь-які контрольні push і production-операції потребують окремої конкретної авторизації.
