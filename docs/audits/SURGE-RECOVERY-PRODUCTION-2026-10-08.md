## Процедура

Штатна Online Backup SQLite spool виконана без перенесення даних на ПК:
SHA-256 `e600a19c5cbcaef7f6ee801064aca3553f5c33443b66b4e0b2b770aa344586bb`.
Збережено точні root-private копії manifest та worker overlay і resolved
конфігурації. Використано чинні чотири Compose files і обидва наявні env-файли.
Плашку підтверджено через public API; витримано 60 секунд.
Collector зупинено штатним control, перед create витримано ≥60 секунд,
перед start — додаткову штатну 60-секундну паузу. Іншого poller не було.
Змінено тільки collector manifest image/source stamp і worker image;
worker effective config порівняно: інші значення незмінні.

Перший server smoke зупинився через недоступність root-private staging
непривілейованому тестовому контейнеру; його повторено з user 0:0 і network none.
Підготовка зупинилася на відсутності другого env-файла у команді Compose;
команду звірено з попереднім deployment controller і виправлено.
Ці дві зупинки відбулися до зупинки/заміни робочих служб; готову spool backup
перевірено за hash і використано повторно без перезапису.

## Межі висновку

Усі чотири підтримувані черги отримують повторну перевірку після нових
даних; успішний прогноз залишається один за годину. Коротка перерва збору
при перемиканні тимчасово порушує необхідну безперервність історії;
`insufficient_history` у цей час є чинною перевіркою якості, не доказом
відмови нового worker. Не знижували пороги й не створювали прогноз без даних.

Модель підтримує ID 1,6,17,29. Ужгород та інші КПП ще не отримали навченої
моделі; повідомлення про фактичне зростання є окремою функцією.
Android-код/APK/Play не змінювали. Перевірки на телефоні в цьому аудиті немає.
Причина попередніх ConnectError — DNS resolution; винного DNS-провайдера
наявні записи не визначають. Нові reason/errno/duration перевірено synthetic
network-none smoke й DB regression; production DNS-помилки не провокували.
