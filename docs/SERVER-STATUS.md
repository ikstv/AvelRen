# Правдива плашка стану сервера

База Android: старий main `4a8e010aeb02d2d77fef3fc1297e67f4f5e5ab27`.
Код перенесено в `apps/android`, версію 0.1.1 та ROAD SIGN збережено.
PR #137 не зливався: він помилково прирівнює `reboot_required` до поточного
перезапуску. Незавершені зміни старої локальної папки не використовувалися.

## Стани

| Сигнал | Напис | Колір |
| --- | --- | --- |
| Немає мережі або Android не підтвердив інтернет | НЕМАЄ ІНТЕРНЕТУ | Червоний |
| Слабкий або нестабільний підтверджений зв'язок | СЛАБКИЙ ІНТЕРНЕТ | Жовтий |
| Підтверджене активне вікно до моменту reboot | ТЕХНІЧНІ РОБОТИ · ДО N ХВ | Жовтий |
| Настав підтверджений момент планового reboot | ПЕРЕЗАПУСК СЕРВЕРА | Жовтий |
| Успішна відповідь зі свіжими даними | СЕРВЕР ОНЛАЙН | Зелений |

Початкову перевірку, неочікувану недоступність API, порожні та застарілі
дані не називаємо вигаданою причиною: діагностичний стан зберігається в коді,
але напис плашки для нього порожній.

Системна перевірка інтернету не є абсолютною гарантією доступу до нашого
сервера: DNS, фільтрація чи TLS теж можуть завадити запиту. Тому цей стан
не називається «сервер перезапускається». Android-адаптер стежить за мережею
за замовчуванням та VALIDATED, а не самим фактом наявності Wi-Fi;
[офіційний опис сигналів](https://developer.android.com/develop/connectivity/network-ops/reading-network-state).

Плашка є лише на головній, на інших вкладках залишається версія.
Кольори беруться з чинних токенів теми. Довгий текст переноситься,
не перекриває назву. На початку показується перевірка, не хибний онлайн.
Годинник стану рухається незалежно від завислого HTTP-запиту. Відповідь
старої мережі не перекриває результат переходу на іншу; refresh серіалізовано.

## Підтвердження планових робіт

Новий публічний `GET /status` (зовнішній шлях `/api/status` за чинним
reverse proxy) повертає лише:

```json
{"maintenance":{"starts_at":"2026-09-27T01:00:00+00:00","restarts_at":"2026-09-27T01:01:15+00:00","ends_at":"2026-09-27T01:10:00+00:00"}}
```

Без чинного вікна: `{"maintenance":null}`. Немає БД-запитів, системних
команд, доступу до єЧерги чи розкриття адміністративної телеметрії.
Вікно читається з `/telemetry/maintenance.json`, шлях можна задати через
`AVELREN_MAINTENANCE_FILE`. Маршрут лише читає; опублікувати вікно через
нього не можна. Відповідь має `Cache-Control: no-store` та штатний rate limit.

Для планового reboot файл містить `starts_at`, `restarts_at`, `ends_at` і
внутрішній `boot_id`. API ніколи не віддає `boot_id` клієнту. Коли після
перезапуску змінюється системна ідентичність завантаження, `/status` одразу
повертає `maintenance: null`, навіть якщо файл ще лежить на диску. Старий
формат лише зі `starts_at` і `ends_at` залишається сумісним як звичайне вікно.
Максимальна тривалість 15 хвилин, планування не далі ніж на добу,
обов'язковий часовий пояс. Відсутній, неправильний чи прострочений файл
не створює ознаки робіт. `reboot_required` не використовується.

Застосунок зберігає всі три моменти підтвердженого вікна локально. До
`restarts_at` він показує технічні роботи, а від цього моменту — перезапуск,
навіть якщо черговий 60-секундний poll ще не встиг отримати помилку. Стан
працює під час недоступності API та після повторного відкриття застосунку,
але автоматично закінчується. Успішна відповідь з null скасовує його. Помилка запиту
не знищує ще чинний кеш. Старий сервер без маршруту сумісний: його 404
не зіпсує успішний результат workload і не ввімкне технічні роботи.
N — округлений угору залишок опублікованого вікна, не гарантія тривалості.

## Межа готовності

Код API й Android реалізовано в новому репозиторії. 27.09.2026 точково
розгорнуто API-модуль та обидва host-скрипти; read-only mount і збіг boot ID
хоста та контейнера підтверджено. Окремий контрольний reboot пройшов усі три
видимі стани на connected-test APK і завершився новим boot ID та зеленим
онлайн-станом. Сам файл не запускає reboot.

Телефон, який не отримав вікно до outage, не може вгадати його причину:
він покаже недоступність сервера. Гарантія пояснення для першого запуску
під час outage потребуватиме незалежного джерела стану або доставки
попередження; цього тут немає. Час спирається на годинник телефона.

Компіляція та JVM-тести не замінюють перевірку екрана на телефоні.
APK у цьому кроці не встановлювався, зміни ще не в main і не в Google Play.
Після дозволеного переходу на main перевірити вузький екран, великий шрифт,
режим польоту, Wi-Fi без інтернету, недоступність API, старі дані й завершення
вікна. Список наступних серверних блоків backup/restore залишається чинним.
