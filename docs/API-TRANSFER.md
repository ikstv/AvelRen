# Перенесення API

## Межі цього кроку

Перенесено API, підписки, схеми запитів, обмеження навантаження, прогноз,
телеметрію та залежності Admin. У [маніфесті](API-PROVENANCE.json) записано
17 вихідних файлів із коміту
`4a8e010aeb02d2d77fef3fc1297e67f4f5e5ab27` старого `ikstv/AvelRen`:
11 модулів, чотири набори unit-тестів і два набори інтеграційних тестів.
Старі коментарі збережено для побайтової перевірки походження.
Після імпорту в api.py додано [публічне вікно робіт](SERVER-STATUS.md);
початковий хеш збережений, поточний зазначено в revision.

Це не розгортання. Робочий сервер, джерело єЧерги, ключі, пристрої й
FCM не використовуються. API читає нашу БД; прямі запити до джерела
залишаються виключно обов'язком collector за [контрактом](../INTEGRATION.md).

## Перевірки

```sh
python scripts/verify_core_provenance.py
python -m pytest -c services/backend/pytest.ini services/backend/tests/unit -q
bash scripts/test_database.sh api
```

Остання команда потребує Docker Compose. Створюється окремий проєкт із
TimescaleDB у tmpfs, без опублікованих портів і зовнішньої мережі під час
тестів. Кожен тест має власну порожню БД; дані лише синтетичні. HTTP-клієнт
викликає застосунок у пам'яті. Обробники працюють під `avelren_api`, а не
під адміністратором БД. Підготовка й видалення тестових даних мають окремий
службовий доступ. Довільні DSN блокуються до збору тестів.

Перевіряються:

- реєстрація, секрет інсталяції, відновлення реєстрації та чужі підписки;
- обсяг тіла запиту, частота запитів і межа одночасних важких операцій;
- черги, історія, свіжість даних, виміряний час в'їзду й стан прогнозу;
- відповідь `503` із `Retry-After` при недоступності БД;
- окреме підтвердження Admin, три спроби, 24 години блокування, повторна
  інсталяція, конкурентні спроби, один адміністратор і відкликання доступу;
- робота основних маршрутів без міграції Admin, на схемі `010`;
- отримання адміністративної телеметрії лише авторизованим адміністратором.

Admin-тести працюють на повній схемі, а не на спрощених таблицях старого
`app/admin_tests/conftest.py`. Перевірка сумісності без Admin використовує
`001`–`010`: міграція `010` надає сервісні права. Це не відтворення ручних
прав поточного production зі схемою `009`.

Окремий workflow `API та адміністрування` працює паралельно з короткими
unit-тестами та тестами міграцій. Android не збирається. Весь API-набір
запускається при зміні його серверних, SQL або тестових залежностей.

## Що ще не готове

Повний lifecycle ETA/сповіщень, модель прогнозування на багатотижневих
даних, довірений reverse proxy, перевірка відновлення резервної
копії й production-збірка потребують наступних блоків. Наявність прогнозу
в коді не означає завершення запланованої AI-моделі або виправлення старих
питань щодо її якості. [Watchdog і телеметричний snapshot](WATCHDOG-TRANSFER.md)
уже перенесені з окремими тестами. Фактична хостова телеметрія цим CI
не перевіряється; відомі обмеження звіту залишаються відкритими.

До дозволеного deployment потрібно зіставити результат із чинною схемою,
правами й конфігурацією production. Наявність API/Admin у репозиторії не
означає, що ці можливості вже з'явилися у користувачів.
