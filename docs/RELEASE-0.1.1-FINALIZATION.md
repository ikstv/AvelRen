## Погоджений екран налаштувань — ще реалізувати

Доручення власника: після поточного серверного етапу, до фінальної збірки.

1. «Про додаток» над адмініструванням: встановлена версія з BuildConfig,
   історія змін за версіями, узгоджена з GitHub release notes.
2. «Адміністрування»: зберегти нинішню піктограму.
3. «Політика конфіденційності»: відкрити чинну політику.
4. Усі три кнопки окремо обвести жовтими рамками за зразком рамок країн
   у виборі КПП: використати наявні дизайн-токени, товщину й заокруглення.
5. Стрілки праворуч ЗАЛИШИТИ: останнє уточнення власника скасовує попередню
   пропозицію прибрати їх. Заголовок «Налаштування» не додавати.

## Admin: уточнення власника про чужий телефон

- Власник входить із підтвердженої інсталяції за чотиризначним PIN.
- Чужа автентифікована інсталяція отримує власне блокування на 24 години
  навіть за правильного PIN. Це не змінює лічильник або блокування власника.
- Повторний запит протягом цього строку не переносить дедлайн.
  Після завершення строку інсталяція не стає дозволеною автоматично:
  нова спроба без схвалення знову блокується.
- Блокування зберігається в devices.admin_blocked_until, нова міграція 013.
  Міграції 001–012 не редагувалися. Це ідентичність інсталяції, не
  апаратний відбиток телефона; нова інсталяція також не має approval.
- Новий код до 013 повертає unavailable для Admin; публічний API працює.
  Три неправильні PIN власника зберігають попереднє глобальне блокування
  Admin на 24 години, яке не скидається перевстановленням.
- Пройшли 188 unit-тестів, 49 API-тестів, 15 тестів міграцій/прав БД і ruff.
  API/БД набори виконані в локальному Docker, окремі tmpfs БД й закриті мережі
  прибрані штатним runner. Обидва pg_dump під backup-роллю успішні.
  Є попередження deprecated TestClient та стандартні попередження TimescaleDB
  про циклічні зв'язки при dump; це не новий restore-тест 013.
  Перший запуск Git Bash зупинився через перетворення /workspace у Windows-шлях;
  повтор із MSYS2_ARG_CONV_EXCL=/workspace пройшов. Docker на ПК працює.
  Ізольований restore зі схемою 013, повний pg_dump backup-роллю,
  новий API/Admin та baseline rollback образ на цій схемі пройшли на
  сервері без зміни робочої БД. Шість CI-перевірок точного head PR #13
  `df7b42a5af1b0c099242ffaf1632f364662c5ab1` успішні.
  Правка ще не злита й не розгорнута.

## Розміщення посилання на єЧергу — ще звірити й реалізувати

Останнє уточнення власника: напис-посилання «Неофіційний застосунок · єЧерга»
залишається на стартових екранах, головному екрані та в моніторингу.
На екранах порога, часу в’їзду та прогнозу його прибрати.
У прогнозі вилучення вже включене до PR #10; перевірити результат разом
з рештою екранів, не видаляти посилання глобально. Записати цю зміну
окремим пунктом підсумкового опису 0.1.1.

## Послідовність випуску

Серверні зміни та їхні перевірки → екран налаштувань і повний перелік змін →
CI/злиття → чиста main-збірка → перевірка власником на телефоні →
GitHub Release з остаточними файлами/хешами → той самий AAB і погоджений
опис у Google Play. Публікація залишається після приймання, не до нього.
