# Канонічні тексти релізу 0.1.2

**Статус: підготовка, не публікація.** Ціль: `versionName 0.1.2`,
`versionCode 5`, Git tag `v0.1.2`.

## Що нового — один текст для GitHub і Google Play

Канонічний файл:
[`apps/android/app/src/main/assets/release-notes/v0.1.2.uk.txt`](../apps/android/app/src/main/assets/release-notes/v0.1.2.uk.txt).

Його вміст має бути **дослівно однаковим** у трьох місцях: на екрані «Про
додаток», у body GitHub Release `v0.1.2` та в українському полі «Що нового»
Google Play. Текст має 150 Unicode-символів і вкладається в ліміт Google Play
500 символів для приміток до версії.

## Основна сторінка Google Play

Це не release notes: короткий і повний опис пояснюють застосунок загалом, а
не конкретну версію. Їхній канонічний текст збережено в
[PLAY-LISTING.uk.md](PLAY-LISTING.uk.md). Ліміти Play: 80 символів для
короткого й 4000 для повного опису. Не дублювати в цих полях повний журнал
змін або серверні обіцянки, яких ще немає в production.

## Межі 0.1.2

У release notes можна заявляти лише дві зміни вище, і лише разом: server-side
self-lock fix PR #37 та Android ID-display PR #38. До публікації потрібні:

- окремо погоджене розгортання #37 із backup, перевіркою та способом відкату;
- AAB з чистого актуального `main`, записом commit, SHA-256 і дати;
- встановлення та перевірка APK на телефоні, зокрема `awaiting_approval`;
- явний дозвіл на GitHub Release і на подання/публікацію у вибраному Play-треку.

Поки ці умови не виконані, не створювати tag, GitHub Release або Play release.
