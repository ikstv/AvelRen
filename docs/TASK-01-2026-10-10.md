## Перевірка підготовчого інструмента

Початковий прогін реально відтворив 12 тестів: 11 успішні, один збій LFS
на Windows через CRLF. Виправлено розпізнавання CRLF, захист вихідного
каталогу Windows DACL, сканування історії цілі та готового кандидата,
перевірку незмінності всіх target refs. Додано негативні тести target scan
та candidate scan; cleanup власного тестового TemporaryDirectory має
обмежені повтори при короткочасному Windows file lock.

Команда `python -m unittest discover -s tools/tests -p
'test_consolidate_legacy_repositories.py' -v`: **15/15, 33.270 s, OK**.
Це синтетичні тести. Реальний prepare/import не запускався: scanner gate
цільової історії не пройдено. Локально також успішні
`scripts/verify_core_provenance.py`, `scripts/verify_android.py` і
`scripts/verify_ci_scopes.py`. CI нового exact head перевіряється окремо
в GitHub; локальні тести не замінюють CI чи production-приймання.

## Повнота файлового реєстру

[files.json](task01-inventory/files.json) містить усі 213 main-файлів AvelRen,
38 main-файлів ops та унікальні ref-tip deltas з усіма ref/commit-входженнями.
Разом 1014 записів: already-integrated 77, superseded-with-evidence 46,
needs-port 132, historical-preserve 759. Кожен має repo/ref/commit/path/blob
та target path або явно відсутнє призначення й причину.

Exact blob/mode, Python AST без docstrings і підтверджені source/current
SHA-256 у provenance розрізняються в причинах. AST не доводить однаковість
залежностей або runtime. 132 needs-port означають потребу предметної звірки,
а не дозвіл замінити сучасну реалізацію старою. Інші refs збережено історично;
проміжні коміти доступні в bundle, але функціонально не прийняті.
[Незалежна звірка](task01-inventory/coverage-check.json) порівняла повні
main trees та всі 23486/3 ref-delta входження без пропусків.

workflow IDs/paths і статус кожної paginated collection. Сирі тексти не

або setting не перенесено; статус reference-only/metadata-only явний.
