# Публічна CPU-телеметрія екрана «Сервер»

Дата: 07.10.2026. Стан: дизайн для погодження, не реалізація чи deployment.

## Мета й погоджений інтерфейс

У налаштуваннях «Адміністрування» перейменувати на «Для адміна».
Вкладка «Сервер» усередині залишається доступною всім; сусідня Admin
та її авторизація не змінюються. Прибрати з цього екрана лічильник
«Активні пристрої», а не серверну функцію обліку пристроїв.

Заголовок — «Стан сервера». Поруч із кнопкою «Оновити» показувати час
останнього вимірювання компактним приглушеним текстом. Кнопка має
щонайменше 48dp зону натиску, попри компактний напис. Нижче — CPU й
відсоток, смужка заповнення 0–100% із градієнтом ROAD SIGN:
зелений #0E7A4E → жовтий #F5C400 → червоний #D5382C.
На 100% заповнення повне, кінцевий колір червоний. Світіння слабке,
статичне, без безперервної анімації чи нових бінарних ресурсів.
При великому шрифті рядок часу й кнопки переноситься, текст не обрізається.

Один запит при відкритті вкладки, наступні — лише кнопкою.
Немає таймера опитування, автооновлення при поверненні фокуса чи
автоматичних повторних спроб. Паралельні запити заблоковані станом busy.

## Варіанти

1. Рекомендовано: додати справжній відсоток CPU до існуючого знімка хоста,
   надати окремий вузький публічний GET. Читання знімка не запускає probe.
2. Вимірювати CPU на кожний запит телефона — відхилено: робота множиться
   на кількість користувачів і API перетинає межу ізоляції хоста.
3. Перетворити load average на відсотки — відхилено: це інша метрика.

## Вимірювання й межа довіри

Існуючий host systemd snapshot лишається єдиним джерелом.
Два читання агрегованого рядка cpu з /proc/stat з інтервалом 1 секунду
визначають частку зайнятого часу всіх CPU: 100 × (delta_total −
delta_idle − delta_iowait) / delta_total. Guest/guest_nice не додаються
повторно до total, бо вже включені в user/nice. Steal входить до busy;
це зайнятість/недоступність CPU віртуальної машини, не лише процес API.
Невалідні лічильники, від’ємні дельти чи нуль total дають null, не 0.
Зберегти час саме завершення CPU-вимірювання та sample_seconds=1:
довший решта probe не має робити CPU старішим непомітно.

Частоту чинного timer не змінювати. API читає готовий атомарний JSON
через наявний read-only mount; нових /proc, Docker socket чи секретних
монтувань у API немає. Немає запитів до єЧерги та змін collector.

## Публічний контракт

GET /api/server/status без адмінських credentials. Відповідь містить
виключно cpu_percent (число 0–100 або null), measured_at (UTC ISO-8601
або null), sample_seconds (1 або null), stale (boolean).
Свіжість визначається часом CPU-вимірювання: понад 300 секунд,
відсутній/невалідний/майбутній timestamp — stale=true й cpu_percent=null.
NaN, infinity, bool, значення поза діапазоном — null, без падіння API.
Інші поля знімка, приватна телеметрія, версії, пристрої та конфігурації
ніколи не проходять у публічну відповідь. Endpoint не звертається до БД.
Не кешувати HTTP-відповідь у клієнті/проксі як свіжу (Cache-Control: no-store).

На старому сервері 404 означає «CPU ще недоступний», а не 0%.
Застарілі/відсутні дані — нейтральна незаповнена смужка й чіткий статус.
Помилка ручного оновлення позначає попередні дані як неоновлені,
не підміняє їх свіжим значенням. Час показується в Europe/Kyiv із датою.

## Перевірка й доставка

TDD: дельти CPU, idle/iowait/guest, невалідні вхідні дані; вузька відповідь
зі знімка, відсутність витоку сторонніх полів, freshness і future-time;
Android parsing/presentation, busy/error та відсутність polling.
Запустити відповідні повні серверні/ops/Android suites, provenance й CI.
Snapshot має контракт script_sha256 — зміни синхронізувати з guard/tests,
не маскувати відставання встановленого production-скрипта.

Preview використовує синтетичні CPU-дані. APK лише з чистої main,
SHA-256 і readback; перевірити 100/130/200%, світлу/темну тему,
0/50/100/null/stale/error і ручне оновлення без адмінського входу.
Офіційний пакет, GitHub Release та Play не публікувати в цьому кроці.
Production rollout потребує окремого GO, свіжої звірки runtime,
перевірки встановленого snapshot/API та конкретного відкату.
