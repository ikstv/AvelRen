# Офлайн-копія AvelRen для доробки екрана

Статус: дизайн на перевірку власника. Реалізацію та встановлення не виконано.

## Мета

Окремий «AvelRen — тест» поруч із Play-додатком: спільні продуктові
Compose-екрани й навігація, але локальні дані замість сервера.
Основна робота — екран прогнозу. Це копія інтерфейсу, не емуляція
справжньої авторизації, Google Play чи доставки FCM.

## Чому потрібне відокремлення даних

Наявний PreviewActivity показує налаштування або SurgeMonitorScreen.
AvelRenScreen напряму звертається до Api й отримує installation через
приведення Application до AvelRenApp. Preview використовує звичайний
Application і не має INTERNET. Просте відкриття головного екрана
не забезпечує ані працездатності, ані потрібної ізоляції.

## Обраний підхід

Відокремити доступ до даних від спільних екранів через передані клієнти.
Продуктові адаптери зберігають чинні Api/InstallationRepository та поведінку.
Preview-адаптери існують тільки у src/preview, повертають локальні моделі
і зберігають тестові підписки в пам'яті. Не копіювати Compose-верстку.
Окремі екрани, які ще мають прямий Api, підключати через той самий підхід
поетапно, без широкого переписування інтерфейсу.

Альтернативи: окремо скопіювати UI — відхилено через ризик розбіжностей;
підключити тестовий APK до production — відхилено через записи й залежність
від доступності сервера.

## Межі й сценарії

- Package ua.avelren.app.preview, назва «AvelRen — тест», окремі дані.
- INTERNET відсутній; Firebase init/messaging, реєстрація й server ACK відсутні.
- Оригінальні теми, навігація й компоненти; тестовий режим чітко позначений.
- Локальний вибір сценарію прогнозу: порожньо, прогноз, факт, немає зв'язку,
  п'ять КПП, недоступний прогноз. Події мають контрольовані строки актуальності.
- «Зрозуміло» й додавання/видалення працюють лише з локальними даними.
- Кнопки серверних/Play-операцій у preview дають явне повідомлення
  «Недоступно в тестовій збірці», не удають реальну успішну операцію.
- Preview не запускає durable server workers. Локальні звукові тести
  відокремлені від перемикання візуальних сценаріїв.
- Офіційний APK, права адміністратора й production не змінюються.

## Перевірки й доставка

Тестувати адаптери й локальні сценарії до реалізації; перевірити regression
продуктових клієнтів, Android JVM/compile/lint та merged manifest ізоляції.
На телефоні перевірити навігацію, сценарії, великий шрифт і прокручування.
Новий кандидат для телефона лише з чистого main після review/CI та інтеграції;
записати BUILD.txt і звірити SHA установленого base.apk.
Зміни інтерфейсу потім робити в спільних компонентах, а не в копії preview.

## Послідовність

1. Відокремити клієнти головної навігації й залежних екранів без зміни UI.
2. Підключити локальні адаптери й перемикач сценаріїв тільки в preview.
3. Пройти перевірки, review/CI, інтегрувати й зібрати чистий main кандидат.
4. Установити поруч з офіційним і доробляти екран за фактичним оглядом.

Цей дизайн потребує перевірки власником, потім окремого точного плану
реалізації. Він не закриває приймання голосу чи публікацію релізу.
