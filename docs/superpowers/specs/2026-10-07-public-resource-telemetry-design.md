# Публічна телеметрія ресурсів сервера

Дата: 07.10.2026. Стан: специфікація для погодження; реалізація й deployment не виконані.

## Мета

Розширити погоджений екран «Сервер» до чотирьох смужок: CPU, RAM,
Disk Memory Usage, Traffic Usage. Показники доступні всім користувачам.
Зберегти ROAD SIGN градієнт, слабке статичне світіння, видимий spinner
замість кнопки та чинний тактильний відгук. Час «Оновлено» означає час
вимірювання даних, а не час натискання кнопки.

## Межі та джерела

CPU використовує чинне вимірювання. RAM — MemTotal мінус MemAvailable;
кеш ОС не трактувати як повністю зайняту пам’ять. Диск — файлову систему,
що містить /opt/avelren; використаний обсяг брати з df, не обчислювати
як total мінус available, бо резерв файлової системи спотворює результат.
Зберігати точні обсяги у байтах; інтерфейс форматує їх у ГіБ.
Тип фізичного носія не показувати: read-only перевірка виявила KVM і
віртуальний QEMU диск, а не підтверджений фізичний HDD/SSD.

Traffic Usage показує вихідний трафік поточного розрахункового місяця
відносно включеного обсягу конкретного сервера. Джерело — Hetzner Cloud
API, не /proc/net/dev: локальні лічильники від запуску не є місячним
обліком провайдера. Значення 20 ТБ не вшивати в код.

## Підходи й вибір

Рекомендовано окремий серверний збирач Hetzner зі знімком: незалежний
від мобільних запитів, легко обмежити частоту й права доступу.
Локальний облік мережі відхилено: не відтворює тарифні винятки провайдера.
Запит до Hetzner на кожне відкриття екрана відхилено: навантаження
множиться на кількість клієнтів і збільшує залежність API від провайдера.

## Потік даних та безпека

Host snapshot додає RAM і точні disk bytes. Окремий плановий збирач
раз на годину читає тільки конкретний сервер через Hetzner API й атомарно
зберігає вузький traffic snapshot. Read-only токен залишається поза Git,
APK та публічним API. Немає агресивних повторів; timeout/429/5xx залишають
попередній знімок із його справжнім часом. Зміна collector єЧерги заборонена.

Публічний /api/server/status зберігає чинні CPU-поля для сумісності,
додає окремі nullable RAM, disk і traffic блоки з використаним/загальним
обсягом, часом вимірювання та stale. Traffic також має ідентифікатор
розрахункового місяця, підтверджений контрактом провайдера; не визначати
його припущенням із локального часового поясу. Ідентифікатори сервера,
IP, токени, конфігурація та решта snapshot не публікуються.
API читає готові знімки без мережевих запитів, subprocess і БД.

RAM/disk застарілі після 300 секунд; traffic — після двох годин або
невідповідності поточному підтвердженому розрахунковому періоду.
Невалідні значення, відсутня конфігурація чи непідтверджений період
дають «Дані недоступні», а не 0%. Збій traffic не ховає CPU/RAM/disk.

## Інтерфейс

Один запит при відкритті вкладки, наступні лише вручну. Автоопитування
телефоном немає. Для RAM/disk/traffic показати використано / загальний
обсяг і відсоток. Traffic містить місяць; використовує ТБ/ГБ відповідно
до байтів провайдера. При перевищенні квоти смужка залишається повною
червоною, але число може перевищувати 100%. RAM/disk понад total невалідні.
Кожен блок має свій статус свіжості; єдиний час не приховує різний вік даних.
Великий шрифт переносить підписи без обрізання. Preview-фікстури чітко
позначені тестовими й не видаються за live-вимірювання.

## Перевірки та доставка

TDD: 0/100%, некоректні обсяги, reserved disk space, відсутні поля старого
сервера, NaN/bool/overflow, future/stale timestamps, зміна місяця,
перевищення квоти, provider errors, атомарність snapshot та public whitelist.
Android: DTO, форматування, часткові збої, single-flight refresh, cancellation,
spinner; offline JVM/compile/lint; перевірка великих шрифтів в обох темах.
Backend і ops: unit/контрактні тести без звернень до реальних джерел.

Окремий PR та запис RELEASE-READINESS. Гілку не зливати без нового дозволу.
Production, встановлення токена/timer і deployment потребують окремого GO.
APK для телефона — лише після погодженої інтеграції з чистої main,
зі звуковим повідомленням перед встановленням та readback SHA-256.

## Перед реалізацією підключення Hetzner

Перевірити офіційний контракт nullable outgoing_traffic, included_traffic
та межі розрахункового періоду. Без підтверджених місячних даних traffic
залишається недоступним. Безпечно перевірити наявність read-only доступу,
не виводячи секретів. Новий токен не створювати без окремого погодження.
