# Зручність FullTest — план виконання

Мета: реалізувати погоджені власником покращення щоденного користування
на чинних Android-потоках. Уточнення власника: **жодних тестових кнопок
чи тестових сповіщень**. Виконання в поточному ізольованому FullTest worktree.

Палітра: чорний/жовтий і білий/червоний. Новий інтерфейс лише за
`ENABLE_TEST_DRAWER`; серверні контракти та production deployment не змінюються.

- [ ] Стан сповіщень: чинні дозволи, канал, звук/гучність і системні обмеження;
  зчитувати повторно після повернення з Android settings, без обіцянки доставки.
- [ ] Обрані КПП: окремі локальні налаштування, швидке перемикання,
  додавання/прибирання з головного екрана й вибору КПП. Не підміняти прогнозні підписки.
- [ ] Актуальність: час вимірювання обраного КПП, застарілі/невідомі дані,
  відсутність мережі або помилка оновлення, явна дія повторного завантаження.
- [ ] Моніторинг: кнопка «Змінити», поточне значення у формі, явне збереження;
  нова ціль створюється до видалення старої. Неатомарний API враховується:
  збій першої дії зберігає стару, збій другої показує обидві та пояснює результат.
  Перевіряти дублікати перед записом; pending-дії блокують повторне натискання.
- [ ] Прогноз: пояснення BETA, очікуваного значення/діапазону,
  чесний час отримання (API не надає часу генерації моделі).
- [ ] Перевірки: логіка обраних/станів/заміни моніторингу з фікстурами,
  full unit/lint/build, свіже APK provenance, обидві теми на телефоні,
  довгі назви, великий шрифт, клавіатура та мережеві помилки.

На телефоні зберігати існуючі дані й параметри; реальні підписки для QA
не створювати. Перевірки зміни серверних цілей виконати через підмінний клієнт.
Фінальні commit/SHA-256/встановлення/сценарії записати в окремому receipt.
