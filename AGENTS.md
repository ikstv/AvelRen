# Правила агентів і розробників

Перед роботою прочитати [правила внесення змін](CONTRIBUTING.md) і
[план перенесення](docs/MIGRATION.md). Код сервера переноситься у
[PR #2](https://github.com/ikstv/AvelRen-ORIGINAL/pull/2).
Документи у гілках і датовані аудити звіряти з поточним станом.

## Де брати ключі й паролі

Перед запитом ключа у власника прочитати [інструкцію доступу](docs/SECRETS-RECOVERY.md).
Там є перевірені комплекти `android`, `server`, `ssh`, `ssh-laptop`, `keepass`,
`certificate` та [команда отримання](tools/Get-ProjectSecret.ps1).
Використовувати наявний вхід GitHub CLI і завантажувати потрібний комплект
поза checkout. Android-паролі, паролі БД та Firebase доступні в комплектах
`android` і `server` приватного релізу: не вимагати для них майстер-пароль KeePass.

Відрізняти завантаження від розшифрування та перевірки актуальності.
Резервний SSH-комплект `ssh` перевірено без passphrase і ssh-agent.
KeePass і passphrase старого ключа `ssh-laptop` ще не відновлено.
Помилка мережі, sandbox або входу `gh` не є доказом втрати ключів.
У звіті вказувати лише шлях, призначення, контрольну суму та результат
перевірки; секретних значень не виводити. Отримання резервної копії не
дозволяє запис на production чи ротацію.

## Незмінні обмеження

- Тільки collector звертається до єЧерги: початки циклів раз на 60 секунд,
  постійний Device ID, запис кожного циклу включно з помилками. Клієнти
  використовують власний API. Не міняти цей механізм під час перенесення.
- Кожен запис на production потребує окремого явного GO на конкретну
  операцію, підготовлених перевірок та відкату. Отримання ключа не є GO.
- Не редагувати застосовані міграції й не виконувати force-push.
  Новим таблицям/послідовностям потрібен явний GRANT SELECT для avelren_backup.
- Секретні значення не комітити; приватні release assets використовуються
  за погодженою [інструкцією](docs/SECRETS-RECOVERY.md).
- APK для телефона — лише з чистої актуальної main; записати коміт,
  дату й SHA-256 та звірити встановлений APK.
- Зберігати чужі локальні зміни. Документувати кожен крок українською.
  Перевірки мають відповідати зміненому компоненту та його залежностям.
- До перенесення повних контрактів використовувати чинні процедури
  [AvelRen-ops](https://github.com/ikstv/AvelRen-ops).
