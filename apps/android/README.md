# Android-застосунок

## Оформлення інших екранів FullTest — 22.10.2026

На прохання власника стиль нового меню застосовано до моніторингу, вибору
КПП, порогів/ETA, прогнозу, інформації та стану сервера, а також вступних
кроків. Кольори Material задано повністю лише у FullTest: чорний/жовтий
або білий/червоний, нейтральні поверхні без зайвого тонування й світіння.
Спільний `FullTestDialog` обмежує висоту, прокручує довгий вміст і залишає
доступними закриття/скасування. За малого екрана чи великого шрифту
прокручується весь діалог. Фільтри мають зони натискання щонайменше 48dp;
погодинний прогноз виводить діапазон на окремому рядку.

Перевірка цієї ітерації: обидві теми на моніторингу, у picker і діалогах,
24-годинному/загальному прогнозі, About та стані сервера; Back/закриття,
прокрутка, landscape і великий шрифт. Створення та видалення підписок не
потрібні для перевірки оформлення. Юридичний текст і обов'язкова згода
вступного екрана збережені. Точні результати й межі — у `dist/BUILD.txt`;
цей опис коду сам по собі не означає проходження телефонних сценаріїв.

## Експериментальне бокове меню FullTest — 21.10.2026

На прохання власника FullTest отримав бокову панель за візуальним зразком
встановленого Dron Alerts: кнопка «Меню» знизу зліва, виїзд панелі за 300 мс,
затемнення основного екрана, округлі групи пунктів і закриття хрестиком,
Back, натисканням поза панеллю або свайпом уліво. Головна AvelRen і її дані
зберігаються; пункти ведуть до чинних моніторингу, прогнозу, теми, інформації
та системних налаштувань сповіщень. Іконки — наявні AvelRen/Material;
чужих бінарних матеріалів у репозиторій не додано.
Палітра й Overpass відповідають AvelRen: у темній темі акцент жовтий,
у світлій — червоний, синій не використовується. Нижній підпис містить
«Developer: Tanko Viktor» і версію; він входить до прокручуваної панелі,
щоб залишатися доступним у горизонтальній орієнтації та з великим шрифтом.
Друга ітерація на прохання власника додає картку обраного КПП та чинний
стан сервера, назви груп і швидкі дії «Обрати КПП» / «Оновити дані».
Вибір використовує наявний picker головної; ручне оновлення — спільний
refresh до API AvelRen з блокуванням повторного натискання на час запиту.
Меню саме не створює підписок і не опитує первинне джерело.

Третя ітерація додає повну нижню панель «Меню / Головна / Моніторинг»,
лічильник активних порогів та ETA, швидке перемикання теми й читабельну
назву КПП з окремою категорією транспорту. Екран налаштувань містить
збережений локальний перемикач «Не гасити екран» (типово вимкнений,
діє тільки поки застосунок на екрані), переходи до Android-налаштувань
сповіщень і батареї, поширення, оцінювання та інформаційні сторінки.
Поширення відкриває системне меню з публічним посиланням
`https://github.com/ikstv/AvelRen/releases/latest`; нічого не надсилає саме.
Оцінювання пояснює статус FullTest та відкриває `ua.avelren.app` у Play
із браузерним fallback. Публічна сторінка Play поки не підтверджена;
доступ і відгуки закритого тестування залежать від акаунта.
Для перевірки: три кнопки панелі, Back із підсторінки до налаштувань,
збереження обох перемикачів після перезапуску, відсутність утримання екрана
у фоні, sharesheet без фактичного надсилання, адресат Play без `.test`,
темна/світла тема, прокрутка та доступність footer у landscape.

Доопрацювання оформлення: BETA біля «Прогноз черги» в drawer,
швидкі кнопки «Поріг авто / Час в’їзду / Прогноз» для обраного КПП,
суцільна нейтральна заливка графіка без стиків і footer без зайвої
градієнтної лінії. Швидкі кнопки відкривають чинні діалоги й прогноз;
створення моніторингу потребує підтвердження. Режим активного екрана
керує Activity window flag безпосередньо та очищує його при вимкненні.

`BuildConfig.ENABLE_TEST_DRAWER` за замовчуванням `false` і вмикається лише
для `-PavelrenFullTest=true` у debug. Звичайна, release та інші тестові
збірки зберігають наявну нижню навігацію. Повторний вибір пункту налаштувань
відкриває його потрібну сторінку; модальне меню першим обробляє Back.

Власник окремо попросив експериментальну APK з цієї гілки та встановлення
поверх поточної `ua.avelren.app.test`. Це дозволений прототип для порівняння
меню, не зміна правила про чисту main для релізних кандидатів.
Під час оновлення застосовується той самий debug-підпис і `adb install -r`.
Коміт, SHA-256 APK, перевірки й телефонний результат фіксуються окремо
у `dist/BUILD.txt`; реєстр етапів — у [RELEASE-READINESS](../../docs/RELEASE-READINESS.md).

Виправлення 15.10.2026: після успішного видалення порога або ETA-цілі
екран одразу викликає звірку сповіщень із `/active-alerts`.
Помилка DELETE не запускає очищення; помилка читання active-alerts
зберігає показані сповіщення. Це доповнює cancel-push і foreground-звірку.
JVM-перевірка порядку та помилки: `MonitorRemovalTest`.
Перевірка нового APK на телефоні ведеться окремо.

База: `ikstv/AvelRen`, коміт `4a8e010aeb02d2d77fef3fc1297e67f4f5e5ab27`,
версія 0.1.1 (versionCode 4). Не застаріла робоча папка й не незлитий PR #137.
Походження 64 файлів: [маніфест](../../docs/ANDROID-PROVENANCE.json).
Зміни плашки: [контракт стану](../../docs/SERVER-STATUS.md).

## Перевірка

Офлайн `-PavelrenUiPreview=true` відкриває спільну навігацію через
`PreviewActivity` з локальним `PreviewAppClient`. Звичайний запуск показує
спільний повнорозмірний інтерфейс із темою ROAD SIGN без службової панелі.
Окремий службовий діалог (лише launch extra `preview_controls=true`) перемикає
порожній список, прогноз, факт, помилку зв'язку, п'ять КПП й недоступний
прогноз. Назва «AvelRen — тест», версія `0.1.3-test`, package `.preview`.
Дані синтетичні; production API/FCM/реєстрація не використовуються.
ACK видаляє локальну подію без server worker. Зміна сценарію оновлює дані
без скидання навігації. `src/previewTest` включається тільки в preview JVM suite.
Телефонний smoke-тест стандартного запуску: `tools/Test-PreviewDefaultScreen.ps1`
із параметрами `-Adb <шлях>` і `-Serial <пристрій>` з кореня репозиторію.
Службове меню відкривається через `adb shell am start -S -n
ua.avelren.app.preview/ua.avelren.app.PreviewActivity --ez preview_controls true`.

Потрібні JDK 17 та Android SDK 36. З цієї папки:

```sh
bash gradlew -PavelrenUiPreview=true :app:testDebugUnitTest :app:compileDebugKotlin --no-daemon --max-workers=2
```

На Windows замість `bash gradlew` використати `.\gradlew.bat`.
Це компіляція та JVM-тести, не встановлення APK. Preview вимикає Google
Services plugin; Firebase-ключі, підпис і реальні мережеві виклики для тестів
не потрібні. Реальний FCM і Play Update цим прогоном не перевіряються.
Окремий workflow Android не запускається від зміни лише серверного коду.

APK на телефон дозволений лише з чистої погодженої main із записом SHA-256
та перевіркою встановленого файла. У цьому PR main не змінюємо, Play-реліз
не публікуємо. Секретні локальні файли й кеші не копіювалися.

## FCM recovery — 12.10.2026

[Контракт та приймання](../../docs/FCM-TOKEN-OWNERSHIP-2026-10-12.md):
єдиний durable coordinator зберігає identity на PUT409, допускає одну
automatic rotation на incident і показує push status/обмежений повтор.
Legacy POST201/PUT200 та new typed409 перевіряються через Ktor MockEngine;
JVM/compile не доводять live FCM або телефонне приймання. Firebase BOM33.7.0
незмінний. До фінальної команди вище можна додати `:app:lintDebug`.
API розгортається першим за окремим GO; старому APK може знадобитися update
через доступний без push канал. APK/phone/Play приймаються окремо.

Whole-branch fix source `5ab29ea4a49dfed1075cd2e935c5db1f7fe2233a`:
301 JVM tests/0 failures/0 errors, compile/lint успішні; lint має
40 warnings/6 hints. Foreground відновлює existing pending після failed enqueue;
same canonical active callback не скасовує worker і не змінює generation.
APPEND_OR_REPLACE додає successor для справді нового candidate; blocked startup
перевіряє SDK token без скидання budget1. Terminal Rejected показує explicit retry,
не запускає rotation для 400/403/422/unrelated409. CI, APK і live FCM — окремі gates.
